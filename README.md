# 📚 AI-Powered PDF Question Answering Assistant (RAG)

An enterprise-grade, memory-efficient PDF Question-Answering system built using **Retrieval-Augmented Generation (RAG)**, **Streamlit**, **FAISS**, and the **Google Gemini API**.

---

## 1. Problem Resolution & Architecture Overview

### Why the Application Was Crashing on Render (502 Bad Gateway & OOM)
On Render's Free tier, services operate with a strict **512 MB RAM limit**. The original codebase used `sentence-transformers`, which pulled `torch` (PyTorch) and `transformers`:
- **PyTorch footprint:** Importing and initializing PyTorch allocates ~350–450 MB RSS immediately.
- **Streamlit footprint:** Streamlit with its dependencies requires ~120–150 MB RSS.
- **Combined memory:** Exceeded **530+ MB**, causing Render's cgroups kernel watchdog to instantly terminate the container:
  ```text
  Ran out of memory (used over 512MB) while running your code.
  ==> Instance restarted
  ```
  Repeated restarts prevented the HTTP health checks (`/_stcore/health` and `/_stcore/host-config`) from passing, yielding **HTTP 502 Bad Gateway**.

### The Solution: Lean, High-Performance Gemini Embeddings Architecture
1. **PyTorch & Sentence-Transformers Removed:** Eliminated the 530MB PyTorch dependency.
2. **Native Gemini Embeddings (`gemini-embedding-001`):** Vector generation is delegated to Google's high-speed embedding API.
3. **RAM Reduced to ~90 MB:** The entire application (Streamlit + NumPy + FAISS + PyPDF + GenAI client) consumes only **~90 MB RAM**, leaving over **420 MB (>80%) of headroom** on Render free tier.
4. **FAISS Compatibility:** The in-memory FAISS index dynamically adapts to the 3072-dimensional vector space (`IndexFlatL2(3072)`) with zero lag.
5. **Exact Frontend Theme Preserved:** The dark-mode UI, styling, cards, layout, user chat, and admin dashboard remain 100% intact.

## 2. Core Features

- **Document Ingestion:** Extract page-by-page text from PDFs with metadata tracking (filename, page numbers).
- **Overlapping Chunking:** Configurable chunk size (500 chars) with 50-char overlap.
- **Vector Retrieval:** In-memory FAISS vector indexing with Euclidean (L2) distance search.
- **Grounded Q&A:** Answers generated by Google Gemini using retrieved context only, complete with page citations.
- **User Interface:** Streamlit dark-mode chat interface with document status card and example prompts.
- **Admin Dashboard:** Password-protected dashboard with metrics, search/filtering, full logs table, and CSV export.
- **Session & State Safety:** Thread-safe SQLite logging, graceful missing secret handling, and non-blocking startups.

## 4. Local Setup and Installation

### 1. Prerequisites
- Python 3.10 or 3.11 recommended.

### 2. Create and Activate Virtual Environment
```bash
# Windows
python -m venv .venv
.\.venv\Scripts\activate

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install Dependencies
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Add your Gemini API key:
```ini
GEMINI_API_KEY=your_gemini_api_key_here
ADMIN_PASSWORD=Admin@12345
```

### 5. Run the Application
```bash
streamlit run app.py
```
Open your browser at `http://localhost:8501`.

## 5. Render Deployment Guide

Follow these exact steps to deploy to Render:

### Step 1: Push Code to GitHub
Ensure all your modified files are committed and pushed to GitHub:
```bash
git add requirements.txt embeddings.py gemini_llm.py app.py retrieval.py vector_store.py pdf_loader.py database.py .streamlit/config.toml README.md
git commit -m "Optimize memory for Render: replace torch with Gemini embeddings, fix 502 Bad Gateway"
git push origin main
```

### Step 2: Configure Web Service on Render
1. Go to your [Render Dashboard](https://dashboard.render.com/).
2. Select your Web Service (or click **New + > Web Service**).
3. Connect your GitHub repository `sivapulluri/PDF-Question-Answering-System`.
4. Configure the following settings:
   - **Environment:** `Python 3`
   - **Region:** Any (e.g., Oregon or Frankfurt)
   - **Branch:** `main`
   - **Build Command:**
     ```bash
     pip install -r requirements.txt
     ```
   - **Start Command:**
     ```bash
     streamlit run app.py --server.port $PORT --server.address 0.0.0.0
     ```

### Step 3: Add Environment Variables in Render
In your Render Service Dashboard, navigate to **Environment** and add:

| Key | Value | Notes |
| :--- | :--- | :--- |
| `GEMINI_API_KEY` | `AIzaSy...` (or your Gemini key) | Required for embeddings and Q&A |
| `ADMIN_PASSWORD` | `Admin@12345` (or your chosen password) | Required for Admin Dashboard login |
| `PYTHON_VERSION` | `3.11.9` | Ensures consistent Python runtime |

### Step 4: Deploy & Verify
Click **Manual Deploy > Clear build cache & deploy**.
Once the deployment finishes:
- Check the logs: Streamlit will start cleanly with `Uvicorn server started on 0.0.0.0:10000`.
- Verify endpoints: `/_stcore/health` returns `200 OK`.
- Access your public URL: The dark-theme UI loads immediately without blank screens or 502 errors.

## 7. Database Persistence Notice (Render Ephemeral Storage)

Render's free tier uses **ephemeral container filesystems**:
- SQLite stores data in `chat_history.db` within the running container.
- If the Render service restarts (e.g. during an idle spin-down or redeployment), the container filesystem resets, clearing the local SQLite file.
- If permanent chat log retention across redeployments is required for production, attach a **Render Persistent Disk** or configure an external database (e.g. PostgreSQL / Supabase).

## 8. Vector Index Compatibility & Rebuilding

- **In-Memory Dynamic Indexing:** The vector store is created on-demand per uploaded PDF session inside `st.session_state`.
- **Dimension Matching:** Chunks and user queries are embedded with the exact same model (`gemini-embedding-001`, 3072 dimensions), guaranteeing 100% mathematical vector space alignment.
- When uploading a new document, simply click **⚙️ Process PDF** in the sidebar. The previous index is safely replaced in memory, preventing dimension mismatch errors.
